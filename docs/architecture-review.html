Problem

Although `src/lib/jobs` is deep for data retrieval, multi-dimension search and filter evaluation is stranded inside a 374-line client component (`job-filters.tsx`). It features no unit tests, duplicates entity definitions with `JobCardProps`, and prevents testing search heuristics (casing, accent insensitivity, multi-field matching) without mounting the entire React DOM.

Solution

Extend the Job module's seam with a pure query/filter evaluator (`filterJobs(jobs, criteria)` or query options in `listJobs`). Re-anchor `job-card.tsx` to consume the canonical `Job` entity, making `job-filters.tsx` a thin presenter.

Benefits

  • ✓ The interface is the test surface: unit test runner verifies token search, status chips, and edge cases in <10ms.
  • ✓ Locality: Job status rules and keyword matching stay inside the Job domain, not in UI state hooks.
  • ✓ Deletion Test: Deleting `JobCardProps` and inline predicate loops concentrates complexity into the deep Job module.
  • ✓ Leverage: Both `/jobs` page and future search bars reuse the same query engine.

Encapsulate Intake File Validation & Purge Residual Modules

Strong cleanup & boundary

Before · Leaking Route Handlers & Ghost Modules

src/lib/rate-limit.ts Shallow utility outside intake module seam

HTTP layer performs business validation; orphan modules cause AI navigation friction.

After · Fully Encapsulated Intake Seam

15 LOC: extracts FormData and directly calls submitApplication. Zero business logic.
Deep Intake Module (`src/lib/intake/`)
Rate Limiter (Internal)
CV & Field Validation

✓ Deleted orphan files: validation.ts & strapi.ts

The transport handler is a razor-thin adapter; all intake constraints live behind the seam.

Problem

While `submitApplication` exists, `api/apply/route.ts` still manually validates file MIME types and enforces the 5MB file size limit before passing buffers. Furthermore, dead residual files (`validation.ts` and `strapi.ts`) remain in `src/lib/` alongside an unencapsulated `rate-limit.ts`.

Solution

Move CV attachment validation (file size and allowed MIME types) directly into `src/lib/intake/validation.ts`. Absorb rate-limiting as an internal adapter within `src/lib/intake/` and delete orphan files (`src/lib/validation.ts`, `src/lib/strapi.ts`).

Benefits

  • ✓ Locality: All business constraints for Candidate Applications reside in one deep module.
  • ✓ AI Navigability: Removing dead files eliminates hallucinations and false search matches.
  • ✓ Deletion Test: Deleting inline checks in `api/apply` concentrates CV validation where it belongs.
  • ✓ Test Surface: CV size and MIME rejection are tested in unit tests without HTTP mocking.

Worth exploring entity alignment

Problem

`article-cards.tsx` masquerades as a generic UI primitive inside `src/components/ui/` while defining its own private `CardArticle` interface that partially overlaps the canonical `Article` entity from `src/lib/articles`. Simultaneously, `src/types/homepage.ts` defines `BlogPreview`, creating three competing representations of an editorial piece.

Solution

Move `article-cards.tsx` to `src/components/article-card.tsx` (or a dedicated presentation module). Replace `CardArticle` and `BlogPreview` with the canonical `Article` entity from `src/lib/articles`.

Benefits

  • ✓ Locality: Domain presentation lives with domain concepts, keeping `components/ui/` pure for generic primitives.
  • ✓ Deletion Test: Eliminating `CardArticle` and `BlogPreview` eliminates type maintenance overhead.
  • ✓ Leverage: Homepage, Articles listing, and Related articles all consume one uniform entity.

Problem

`about/page.tsx` is a 459-line file that directly imports static JSON from `@/Data/about.ts`, embeds 10 SVG icons directly in its body, and bounces across 4 shallow satellite modules. Although Strapi supports an "About" single-type, there is no domain module or seam to absorb CMS changes.

Solution

Establish an `About Profile` module (`src/lib/about/`) with a `getAboutProfile()` interface backed by static and Strapi adapters, mirroring the Jobs/Articles pattern. Collapse shallow satellites (`bio-expand`, `headline-pills`) into cohesive section components.

Benefits

  • ✓ Architectural Consistency: All core domain entities (Jobs, Articles, About) follow the dual-adapter repository pattern.
  • ✓ Locality: Biographical data resolution and localization live behind one seam.
  • ✓ Deletion Test: Eliminating scattered satellite modules reduces file-hopping friction.
Recomendación Principal Mayor Apalancamiento (Highest Leverage)

Candidate 1: Deepen Job Filtering & Query Seam into Job Repository →

El subsistema de Jobs es el núcleo funcional y el área de mayor valor para los candidatos y clientes. En este momento, la recuperación de datos ya es un módulo profundo, pero toda la lógica de búsqueda tokenizada, filtrado por estado y chips de modalidad está atrapada dentro de un componente de UI de 374 líneas sin pruebas unitarias. Al absorber el filtrado detrás de la costura del módulo Job Repository, logramos que la búsqueda sea 100% testeable en milisegundos con Node test runner y unificamos la entidad Job eliminando interfaces redundantes como JobCardProps.
